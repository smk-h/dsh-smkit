本文说明 dsh-smkit 的「MCP 管理」：在「设置 → MCP」页登记、启停与维护 MCP 服务器，涵盖工作区隔离与连接归属、工具清单、按需代理、调用超时、掉线自动重连与命名规则。

## 一、 服务器与作用域

「设置 → MCP」页统一登记、启停、编辑、删除 MCP 服务器，停用的服务器不会在启动时被拉起：

- **传输**：远程 HTTP 支持 OAuth PKCE + 动态客户端注册、静态 Bearer Token 与无鉴权三种认证，无鉴权模式不发送 `Authorization` 头，适合本机这类不做认证的端点（如 `http://127.0.0.1:9316/mcp`）；本地 stdio 直接拉起子进程。
- **工作区隔离**：工作区独享的服务器写在 `<workspace>/.dsh/dshmm/mcp.json`，全局服务器也可按工作区屏蔽；作用域选择旁可一键打开当前生效的配置文件（全局为 `~/.dsh/mcp-manager.json` 状态文件，工作区为该工作区的 `mcp.json`）。连接在会话之间如何复用与释放，见「五、连接归属与生命周期」。
- **命名**：服务器名取 1～32 位 `[A-Za-z0-9_-]`，与工具原始名拼成模型可见的 `mcp__<服务器名>__<工具名>`；不同工作区可声明同名服务器，规则见「四、命名规则」。
- **与上游共存**：同一个 profile 若还装着 `dsh-mcp-manager`（本插件的前身），本插件的 MCP 部分**自动退避**：不注册 `mcp__*` 工具、不提供 `/mcp` 命令、不占用 `mcp` 语言命名空间、设置区不显示 MCP 页，MCP 全部交给上游；技能、主题、大纲、通知等功能照常。判据是 profile 的 `dsh.profile.bundles`——装了但没被加载不会触发退避，两个都加载时也只有一个在管 MCP。改动装配或语言命名空间后，用 [`test/cases/LV006-MCP上游共存退避.md`](../test/cases/LV006-MCP上游共存退避.md) 复验两种装配。
- **运行时控制**：可重启或关闭单个服务器的连接，长连接断开后不必重启 dsh；「高级」里还可开启掉线自动重连，由插件自己发现并重建连接（见「三、掉线自动重连」）。
- **接口准入**：插件自己的 HTTP 接口（`/smkit/api/*`）走 DSH 的准入判定——没有 DSH 会话 401，Host/Origin 不符 403，宿主没有 `connection` 服务时 503 而不是匿名放行；OAuth 回调页豁免会话校验（IdP 跳转不带 cookie），由回调自身校验 `state`。

## 二、 工具暴露与调用

### 1. 工具清单

已连接的服务器不只知道「有几个工具」：

- 行上是一句可点开的工具摘要（`N 个工具` + 折叠箭头），点开才列出注册的工具名——几十个工具也只是一行，不点不占地方。
- 鼠标悬浮、或用键盘 Tab 到某个工具名，弹出该工具在服务端声明的原始描述与入参（参数名、类型、是否必填与说明）；浮层可滚动、可走进去看，点它不会消失，文字可直接选中复制。

### 2. 按需工具代理

「设置 → MCP」页提供「按需 MCP 工具调用」开关（可选）：开启后该 MCP 仅暴露 search、describe、execute 三个 broker 工具，避免几十个工具一次性占满上下文。三个工具各自怎么工作、什么时候注册、开关前后有何差别，见 [LV002-MCP按需工具代理](LV002-MCP按需工具代理.md)。

暴露方式随宿主能力而定：DSH 0.2 不再把工具清单交给 `system-prompt/assemble`，插件改为给每条注册打 `deferLoading` 标记，由宿主决定怎么用——路由声明了 `toolUpdate` 时这些工具延迟加载、不占请求体积；路由没声明（多数 OpenAI 兼容模型就是这种）时宿主会立即下发，插件随即把完整定义换成**同名短桩**（描述一行、参数表留空，完整 schema 用 `mcp_describe_tool` 取），从第二轮起生效。0.1 沿用原来的清单过滤。两条路径都保留工具的可执行性，`mcp_execute_tool` 与 `/mcp call` 走同一套放行。改动这块后用 [`test/cases/LV007-MCP影子桩.md`](../test/cases/LV007-MCP影子桩.md) 复验。

### 3. 工具调用超时

「设置 → MCP → 高级」可配置工具调用超时，默认 60000 毫秒，范围 1000～1800000：

- 只作用于 `tools/call`；连接阶段（`initialize` / `tools/list`）仍是固定 60 秒。
- 保存后立即生效，不需要重连服务器，也不需要重启 dsh。

### 4. 斜杠命令 `/mcp`

`/mcp` 是宿主侧的直调入口：命令在宿主进程里执行，不经过模型、不消耗 token，结果也不进入会话上下文。它落到与模型同一个 MCP 连接上，串口、SSH 这类有状态资源因此是连续的。

- `/mcp list`：列出当前项目可见的 MCP 服务器，以及每个服务器暴露了多少个工具。
- `/mcp list <服务器>`：列出该服务器的工具（最多 50 条）。
- `/mcp help <工具名>`：显示该工具的调用示例（先给最短可用形式，再给带可选参数的完整形式，可直接复制粘贴，枚举值取真实取值）与参数清单（必填标 `*`，带类型、说明与枚举值），不执行。不带工具名时打印用法；`describe` 是同义旧写法。
- `/mcp search <关键词>`：在所有可见工具里按关键词检索。
- `/mcp call <工具名> [JSON]`：按精确名调用，参数是一个 JSON 对象；缺必填参数时不会执行，而是把参数清单打出来——不必先猜一遍。

**面板**：输入 `/mcp` 后按 Tab（或在斜杠菜单里选中它），打开的是与 `/model` 同一个选择面板——按服务器分组列出当前项目可见的工具，可直接输入关键字过滤（组标题就是服务器名）。选中工具行立刻执行 `/mcp help <工具名>`，卡片里给出可复制的 call 示例与参数清单；每个工具还多一行「补参数」，这一行**不执行**，只把命令填进输入框、光标停在末尾——工具声明了几个参数就补几个占位实参（按 schema 声明顺序，如 `/mcp call <工具名> {"name":"…","baud":0}`）：字符串是 `…`、数字与整数 `0`、布尔 `false`、数组 `[]`、对象 `{}`，服务端给了 `enum` 或 `default` 就取它的值；一个参数都不声明的工具才是裸调用 `/mcp call <工具名> `。改完再回车。之所以不再有第二级：`/mcp` 之后的空格已经把这一行交给参数输入，此后没有任何补全入口，面板内的搜索承担同一件事。

三条都只认**当前项目**可见的工具：工作区服务器的工具注册在该会话的 agent 作用域里，别的项目看不到。开启「按需工具代理」后，命令会带上 broker 的放行标记，因此与 broker 的三件套走同一条执行管线（guard、权限、调用日志一致）。宿主没有命令服务时（较旧的 shell 或精简 profile），命令静默缺席，其余功能不受影响；宿主没有命令 UI 服务时，面板缺席，命令本身照常可用。

## 三、 掉线自动重连

同一个「设置 → MCP → 高级」里的「自动重连」块（默认开启）：传输断开后插件自己重建连接，不必手动点「重启」，也不必重启 dsh。

- **只对「连上过、又掉线」的连接重试**。所谓重连，前提是它真的连上过：第一次就没连上的（地址不通、命令写错、令牌没配、还没走完认证跳转）原样留着，不排队重试；已经处于「待认证」的也不会被反复敲门。这条规则同样延续到重试链里——重试过程中若落到需要人处理的状态（最典型是「待认证」，比如令牌过期且刷新失败），就地停手并把决定权交回给人，而不是一直敲。
- **两种掉线都发现得了**。一是**子进程退出**——stdio 服务器的子进程自己死了就立刻触发重连；远程 SSH 场景下这个子进程正是 `ssh` 通道本身，链路断掉它就会退出，所以这条路是即时的。二是**链路半死**——进程还在、会话已经没了（半开 TCP、卡死的通道），这种情况没有任何信号，靠「探活间隔」定期发一次 `tools/list` 去问，问不通即算掉线。
- **`tools/call` 失败不触发重连**。工具返回 `isError` 和传输层断掉在这一层是同一种错误形状，据此重连会因为一次普通的工具报错就把好连接拆掉；退出信号加探活已经覆盖了同类情况，不必猜。
- **退避与放弃**：重试间隔从 1 秒起翻倍，到「重试间隔上限」（默认 30000 毫秒，范围 1000～600000）为止，带 20% 以内的抖动；「最大重试次数」（0～100）填 0（默认）表示不限制、一直重试。
- **探活间隔**（默认 30000 毫秒，范围 0 或 1000～600000）填 0 就关掉探活，只留子进程退出信号。
- **状态可见**：重连期间该行显示「重连中」并继续转圈，行内的错误文字写明原因和下一次重试的时间；次数用尽则落到「错误」并注明已放弃。
- **主动停止优先**：重启、关闭、停用、删除、工作区释放、插件卸载都会取消已经排上的重试——否则刚点完「关闭」，2 秒后又被拉起来。
- **落在哪**：四个值写入 `~/.dsh/mcp-manager.json`（`autoReconnect`、`reconnectMaxAttempts`、`reconnectMaxDelayMs`、`healthCheckIntervalMs`），保存后立即生效，下一次掉线就按新值走。
- **SSH 侧建议**：链路真的断掉时，本地 `ssh` 得自己先察觉才会退出。给参数补上 `-o ServerAliveInterval=60 -o ServerAliveCountMax=3`（每 60 秒一个保活包，连续 3 个无应答即断开退出）后，空闲连接不会被 NAT/隧道回收，断线也能在 180 秒内被 ssh 自己发现；不加也能跑，只是最坏要等一个探活周期再加一个请求超时。
- **怎么手动验证**：[`scripts/ssh-stub-mcp.mjs`](../scripts/ssh-stub-mcp.mjs) 是一个会自己断开的 MCP 服务器，经本地回环 ssh 拉起即可复现掉线与重连；配置写法和判据表见 [`docs/LV001-MCP功能测试.md`](LV001-MCP功能测试.md) 的「二、6」与「四、7」。

## 四、 命名规则

服务器名取 1～32 位 `[A-Za-z0-9_-]`：全局服务器是 `~/.dsh/mcp-manager.json` 里 `servers[].name`，工作区服务器是 `<workspace>/.dsh/dshmm/mcp.json` 里 `mcpServers` 的键。它会直接成为工具名的前缀，因此不允许其他字符。

工具对模型暴露的名字是 `mcp__<服务器名>__<工具原始名>`：

- 两处分隔符都是双下划线；工具原始名里非 `[A-Za-z0-9_-]` 的字符一律替换为 `_`（服务器名本身已受上面的字符集约束，不需要替换）。
- 公开名超过 64 字符时，保留前 51 个字符再补 `_` 与 12 位 sha256 后缀，避免不同工具因截断而撞名。
- 工具描述末尾附带 `[<服务器名> MCP]`，名字被截断后仍能看出它属于哪个服务器。
- 公开名的拼接与 dsh 内置 MCP 客户端逐字节一致，按名字反查服务器的调用方不必改动。
- 改服务器名会连带改变工具的公开名，此前按旧名字引用过它的会话与指令需要同步更新。

名字的唯一性按作用域划分，与工具的可见范围一致：

- **全局层全局唯一**：全局服务器的工具注册进共享的根注册表，每个 agent 都看得到，因此名字不能重复。
- **工作区层只避让全局层**：不同工作区可以声明同名服务器，各自独立进程、独立连接、独立凭据；工具注册进该工作区 agent 自己的注册表，所以不会有 agent 同时看到两份 `mcp__<名字>__*`。
- **同一工作区内唯一**：`mcp.json` 里 `mcpServers` 的键本身不重复。

在设置页新增或改名时，重名会被直接拒绝（409）；手写的 `mcp.json` 与全局服务器重名时，该行以「冲突」呈现并在行内给出错因，服务器不会被拉起。工作区层只避让全局同名，全局层还会计入当前已打开工作区的占名。

## 五、 连接归属与生命周期

「一条连接」在两种传输下各指一样东西：stdio 服务器是一个子进程（`command` 拉起的那个），HTTP 服务器是一个 MCP session（`initialize` 之后带 `Mcp-Session-Id` 的那个）。插件只按两层归属管理连接，共享还是隔离全由这一层决定。

### 1. 谁和谁共用一条连接

| 场景 | 是否共用 | 说明 |
| --- | --- | --- |
| 同一工作区的多个会话 | 共用 | 连接按「工作区路径 + 服务器名」登记，工作区内所有会话指向同一条 |
| 不同工作区各自配置同一个 MCP | 不共用 | 各自一条连接；stdio 是两个子进程，HTTP 是对端多一个 MCP session |
| 全局层登记的服务器 | 所有会话共用 | 按服务器 id 只开一条，工具注册进共享的根注册表 |
| 全局层与某工作区同名 | 只跑全局那条 | 工作区这条标「冲突」，不会被拉起 |
| 工作区 `exclude` 某个全局服务器 | 连接照旧 | 只屏蔽该工作区会话对这些工具的可见性 |

工作区之间的隔离是刻意的：两个工作区声明同名服务器时，工具公开名会一样（`mcp__<名字>__*`），但各自注册进自己 agent 的注册表，没有 agent 会同时看到两份。需要跨项目共享同一个有状态服务器时，正确做法是登记到全局层，而不是在每个工作区各写一份。

掉线重连不改变上面任何一条：它重建的是同一份连接记录（全局按服务器 id、工作区按「路径 + 服务器名」找回原记录），因此重连前后仍是同一条连接、同一套共享关系。

### 2. 什么时候连、什么时候断

- **全局层**：插件加载时连上所有启用的服务器（停用的保持休眠，HTTP 缺凭据的落到「待认证」），此后随 dsh 进程存活，直到停用、删除、重启或插件卸载——与当前有没有会话无关。
- **工作区层**：在该工作区打开第一个会话（创建或恢复）时读 `mcp.json` 并连接，连接在后台进行，不阻塞开会话；同目录之后打开的会话直接复用已连好的连接。
- **工作区释放**：最后一个会话的作用域拆掉时，该工作区的连接全部关闭、运行时记录一并删除；下次再打开要重新连接，进程里的临时状态（`stty`、shell 登录态）不会保留。
- **掉线重连**：连接掉了由插件自己重建，重建的是**原来那条连接记录**——全局层回到服务器 id 那一条（重开前先收掉旧 transport），工作区层回到「该工作区 + 服务器名」那一行，成功后原地刷新工具注册与该工作区 agent 的作用域，所以共享关系与连接身份都不变，重连期间该行显示「重连中」。只有「连上过、又掉线」的连接会重试，重开成功即清零重试计数；最后一个会话释放、停用、删除、重启都会取消已排上的重试，不会出现「刚关掉又被拉起来」。判定条件与退避参数见「三、掉线自动重连」。
- **配置变更**：`mcp.json` 由 `watchFile` 轮询发现（250 毫秒探测、300 毫秒防抖后重扫），只有真正改过的条目才重连，其余保留原连接，因此改一个服务器不会把同工作区的其它服务器一起重启。
- **边界情况**：工作区层按 agent 对象计数。同一会话重开时，若旧 agent 的释放早于新 agent 的加入，计数会瞬时归零、连接随之重建；有会话重叠时则直接复用。

### 3. 选作用域时的几条建议

- **独占型资源放全局层**：串口、单实例 SSH 通道这类同一时刻只能有一个占用者的服务，全局层只起一个进程；若每个工作区各配一份，就成了两个进程抢同一个设备。
- **要按项目隔离的放工作区层**：工作区层天然是独立进程，配置、凭据、进程内状态都不外溢，适合各项目参数不同的工具。
- **共享会话态是双刃剑**：同一工作区里一个会话登录的 shell、打开的串口会话，另一个会话调用同一个工具时看到的是同一份状态，省去重复登录；代价是并发调用打在同一条管道上，时序要自己安排。
- **屏蔽不等于关闭**：「工作区屏蔽」只让该工作区的会话看不到那些工具，全局进程继续为其它工作区服务；真要停掉，必须在全局层停用或关闭它。
