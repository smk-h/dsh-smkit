本文说明 dsh-smkit 的「添加到对话」：在右侧栏的只读文件预览或终端里选中文本，**右键**会弹出插件自己的菜单卡：一行把这段内容写进当前会话的输入框草稿，一行原样复制，不必先复制、再切到会话、再粘贴。实现见 [`src/client/features/selection-quote/`](../src/client/features/selection-quote/)。

## 一、 为什么是右键菜单，而不是浮出按钮

早先的形态是选区末端自动浮一个按钮，但它的锚点只能是手势结束的位置，在边界上不可救：贴着预览上沿松手会被预览头部与上方标签条盖住，拖过窗口下沿松手会被画到视口外（看起来就是「没有弹出来」）。右键天然指向读者正在看的那段文字，卡片开在指针处、由宿主 `Menu` 自己测量并夹进视口，因此边界上唯一可靠的入口就是它——所以浮出按钮已整体移除，选中本身不再画任何东西。

## 二、 插入什么

- **文件预览**：插入一段围栏代码块，信息行是 `path:start-end`（单行只有 `path:12`，行区间未知时只有 `path`），正文是选中的原文。路径按会话 cwd 相对化，与预览头部显示的一致；cwd 读不到时保留绝对路径。行号从渲染 DOM 读出：高亮渲染器按行位置计数，纯文本渲染器读每行自带的编号，渲染后的 Markdown 文档没有源码行，因此只写路径。超过 500 字符的选区只写信息行——对文件而言「路径 + 行号」本身就能定位，整段正文只会灌满草稿。
- **终端**：xterm 的选区存在模拟器自己的模型里（根元素不可选中，`window.getSelection()` 读不到），所以经它装在根元素上的 copy 通道读取——派发一个带 `clipboardData` 接收器的 `copy` 事件，xterm 会把选中文本回填进来；全程不碰真实剪贴板、不依赖快捷键，也与渲染器无关。终端选区没有路径和行号可标注，插入的是信息行为 `console` 的围栏块，并且**不设长度上限**：没有可回退的信息，截断就等于丢内容。

## 三、 复制、接管与共存

- **复制一行**：放进去的是选区原文，不是带围栏的块（粘贴回文件时不该带围栏），也就是原生菜单里唯一值得留下的那一行。复制成功后卡片原位置留一条约 1.2 秒的「已复制」，写入被浏览器拒绝时什么都不显示；写入优先走宿主的 `writeClipboard`（带 `execCommand` 回退，非安全上下文也能用），没有该模块时才用 `navigator.clipboard`。
- **接管条件**：指针落在这块表面的可选中区域、且存在有效选区时才替换原生菜单；指针不在这块表面（例如会话输入框、预览头部）或没有选区时不接管，原生菜单与终端自己的右键行为照旧。键盘的菜单键（`contextmenu` 无坐标）落在选区末端。没有 `Menu` / `createRoot` 的宿主上整条路径退场，读者保留原生菜单（本功能的 React 根要到第一次右键才挂载，平时不占 DOM）。
- **与 `dsh-better-sidebar` 共存**：加载它**不会**让本功能让位。它的编辑器是它自己的 tab 体（`data-dsh-native-tab-host`，CodeMirror 或它自己的 Markdown 预览），既不匹配本站读的宿主标记，也没有注册 `contextmenu`——它的「添加到对话」浮层挂在自己的 `mouseup` 上。两块表面互不相交：它的编辑器里右键仍是浏览器原生菜单（那里的添加由它自己的浮层提供），宿主的预览与终端里则是本功能的卡片；它主动让回宿主的文件（图片、PDF 等宿主自有渲染器）仍落在宿主预览里，那里的右键卡片是唯一入口。
