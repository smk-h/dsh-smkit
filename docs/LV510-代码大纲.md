本文说明 dsh-smkit 的「代码大纲」：在右侧栏打开 C 族源码预览时，列出顶层的函数、结构体、联合、枚举与函数式宏，点一下跳到对应行。

## 一、 怎么用

### 1. 打开与关闭

按钮出现在**当前显示这个文件的那一面**上，两种都支持：

- 宿主只读预览：按钮在头部、刷新按钮的左边；
- 编辑器标签页（装了 `dsh-better-sidebar` 时文件开在它的 CodeMirror 里）：按钮在路径输入框所在那一行的末尾。

点它展开面板，再点收起；点击面板外部或按 `Esc` 也会收起。

- 面板第一次打开时才向后端要数据，同一个文件再次打开直接复用，不再请求。
- 切到另一个文件时旧面板立即关闭，符号不会串到新文件名下。
- 读取失败时面板里显示宿主给的原因，并留一个「重试」。

### 2. 认哪些文件

只对能读的扩展名出现按钮，目前两族：

- C 族：`.c`、`.h`、`.cc`、`.cpp`、`.cxx`、`.hh`、`.hpp`、`.hxx`、`.ino`、`.m`、`.mm`；
- JS 族：`.js`、`.jsx`、`.mjs`、`.cjs`、`.ts`、`.tsx`、`.mts`、`.cts`；
- Shell 族：`.sh`、`.bash`、`.zsh`、`.ksh`，以及 `.bashrc`、`.zshrc`、`.profile` 这类**按文件名**认的 rc 文件。

Markdown、图片、PDF 这些没有行可跳的预览不会出现按钮。清单只有一份（`shared/outline/languages`），界面与宿主读的是同一条。

头文件与源文件有一处刻意的差别：头文件里的函数**原型**也会列出，因为原型就是头文件对外提供的东西；源文件里原型通常与定义成对出现，列出来会让每个函数重复一趟。同一开关也让头文件模式把 `struct X;` 这类前向声明列为类型——它在头文件里确实是接口的一部分。

## 二、 符号从哪来

### 1. 不由页面读

宿主的代码预览是**分页**的：长文件按页追加，往下滚才加载下一页。页面里只有已经加载的那几页，从 DOM 里数函数，得到的只是「第一屏有哪些函数」，文件越长错得越多。

所以符号由宿主半区读取整份文件后扫描并返回，界面只负责列出结果和发起跳转。

### 2. 宿主侧的接口

一条只读路由：`GET /smkit/api/outline?path=<绝对路径>`，返回 `{ symbols: [...] }`，每项含 `kind`、`name`、`line`。

拒绝的情况各有稳定编码，便于界面区分：

| 编码 | HTTP | 含义 |
|---|---|---|
| `outline/not-absolute` | 400 | 路径不是绝对路径 |
| `outline/unsupported` | 415 | 扩展名不在支持清单里 |
| `outline/missing` | 404 | 文件不存在 |
| `outline/not-file` | 400 | 存在但不是普通文件 |
| `outline/too-large` | 413 | 超过 4 MB |
| `outline/unreadable` | 500 | 读取失败（权限、IO） |

编码按 UTF-8 读取；若出现替换字符（Windows 上以本地代码页保存的 C 文件很常见），改用 GB18030 再读一次——否则多字节字符里的某个字节会被当成引号或注释符，把后面的声明整个吞掉。

## 三、 扫描规则

### 1. 先抹掉不该有声明的地方

（1）预处理行整行抹空（含 `\` 续行），同时记下**函数式**宏的名字（`#define NAME(` 这种），对象式宏不入表。

（2）注释、字符串、字符字面量逐字符抹成空格，但**保留换行**——行号因此不会偏移，跳转才落得准。

### 2. 再按括号深度认声明

只在花括号深度为 0 的位置判定。C 族的默认形态有两类：

- `{` 之前的语句里有「标识符 + `(` … `)`」→ 函数，行号取语句起点（返回类型那一行），而不是函数名或 `{`；
- `{` 之前是 `struct` / `union` / `enum` / `class` 且标记名是语句最后一个词 → 聚合类型；
- `typedef struct { … } Name;` 这种匿名的，名字在右花括号之后取。

几条反例规则：`struct Point p = {0};` 是变量不是类型，不列；`static void (*handler)(int) = 0;` 是函数指针变量，不列；`if/for/while/switch/sizeof` 等控制词后面即使跟括号也不是函数。

`namespace X {` 与 `extern "C" {` 是**透明**的容器块：块内的声明仍按顶层处理。否则 C++ 里所有类外定义都在命名空间里缩了一层，大纲会整份空掉。类体与函数体则不透明，里面的东西一概不收集。

### 3. 已知边界

这是**语法层**的扫描，不是语义分析，因此：

- `#if 0` 里被注释掉的定义仍会被列出；
- 宏展开生成的声明看不到；
- K&R 风格的老式参数表读不到（名字后面先声明参数、再开函数体的写法）；
- 运算符重载不列出——`(` 前是 `==` 这类标点，不是名字；
- 类内成员与嵌套类型不列出，只收集顶层声明；
- `= default` / `= delete` 的成员定义没有函数体，不列出；
- 模板定义的行号落在 `template <…>` 那一行，而不是函数名那一行。

JS 族另有一组边界：

- `type Name = …` 类型别名不列出（没有可跳的块，种类里也没有对应项）；
- 重载签名按语句各列一条，实现体再列一条，同名会出现多次；
- 立即执行函数、`setTimeout(...)` 这类调用不列出；
- JSX 里的组件与函数体内的声明不列出（函数体不透明）。

Shell 族的边界：

- 只列函数，不列变量、`alias`、导出；
- `if` / `case` / `for` 的分支体不是花括号块，写在这些分支里的函数会被当作顶层函数列出；
- 一行多个命令时以 `;` 分隔的语句不参与判定，因此 `f() { :; }; g() { :; }` 只列出 `f`；
- fish 的 `function name … end` 没有花括号，不在支持范围。

这些对「读文件时找个函数」够用；需要语义精度时见最后一章的取舍。

## 四、 按语言拆分的结构

### 1. 三层，一份 profile

扫描拆成互不重叠的三层，新增语言只动第三层：

| 层 | 位置 | 职责 |
|---|---|---|
| 词法 | `host/features/outline/syntax.ts` | 按规则遮蔽注释、字面量、预处理行，再把剩下的切成 token。与语言无关，规则由 profile 提供 |
| 遍历 | `host/features/outline/scan.ts` | 维护花括号栈（区分透明容器与不透明块）、缓冲语句、在边界处调用判定。与语言无关 |
| 判定 | `host/features/outline/profiles/*.ts` | 关键字表、聚合关键字、容器块、额外符号（宏），必要时整体接管判定 |

profile 可填的项依次是：`syntax`（注释/字符串/是否预处理）、`aggregates`（关键字 → 种类）、`noise`（带括号但不是声明的词）、`typeWords`（能站在名字位置上的词）、`aliasKeyword`（`typedef` 这类）、`containers`（透明块）、`markers`（遍历之外的符号）、`prototypes`（哪些后缀列原型）、`startsStatement`（无分号语言的语句边界）、`accept`（整体接管判定）。

### 2. 加一门语言要做什么

1. 在 `src/shared/outline/languages.ts` 里加一行 `{ id, extensions }`——两端的扩展名清单是同一条，界面不会为一个宿主读不了的文件画按钮。
2. 在 `src/host/features/outline/profiles/` 下新建 `<语言>.ts`，导出 `SourceProfile`。
3. 在 `profiles/index.ts` 的 `PROFILES` 里登记这个 id。
4. 单测：`test/outline.test.mjs` 里加一组用例；也可以往 `.tmp/outline-fixtures/` 放样本，再 `node .tmp/outline-fixtures/check.mjs --update` 建立基线。

大多数大括号语言**只需要数据**：`struct/class/enum` 之类关键字扔进 `aggregates`，`if/for/return` 扔进 `noise`，就够列出顶层函数与类型。需要写代码的只有三种情况：语句不以 `;` 结尾（提供 `startsStatement`）、声明形状与「名字 + 括号」不同（提供 `accept`）、符号不在语句里（提供 `markers`）。

### 3. 已接入的三种

- `c-family`：C、C++、ObjC、Arduino 的 `.c .h .cc .cpp .cxx .hh .hpp .hxx .ino .m .mm`。头文件模式列原型与前向声明；`namespace` / `extern "C"` 是透明块；函数式宏额外列出。
- `js-family`：`.js .jsx .mjs .cjs .ts .tsx .mts .cts`。类按 `class/interface` 判定（`extends` 之后仍能取到名字）、`enum` 取标记名、`const f = () => {}` 与 `exports.f = function () {}` / `原型方法` 都列出；没有头文件概念，所有以 `;` 结束或以声明关键字开头的语句都参与判定；模板字面量整体遮蔽。
- `shell-family`：`.sh .bash .zsh .ksh` 与 shell 的 rc 点文件。`name() {` 与 `function name {` 两种写法都认；`#` 只在词首算注释（`${p#prefix}`、`$#` 是展开）；heredoc 的整段正文按数据抹掉，且**找不到终止符时整体放弃**——否则字符串里一个 `<<EOF` 会把后面的脚本全吃掉；换行即语句边界（shell 没有分号分隔）。

## 五、 点击跳转

### 1. 落点

点击条目后，目标行落在预览可视区的上三分之一处，并保留约 1.2 秒的高亮——与「跳转到行」功能留下的视觉标记同一套观感。

### 2. 分页推进

目标行还没加载时，按宿主自己的「加载更多」按钮逐页推进，每页等一小段时间再看，直到出现或预算耗尽；预算用完就落在最后一行，不会静默失败。编辑器标签页里没有分页（CodeMirror 载入整份文档），直接按行号定位。

这套推进逻辑放在平台层（`src/client/platform/ui/preview-lines.ts`），与「跳转到行」用的是同一份行模型；两者的差异只在于落点之后各自画什么。

## 六、 与邻居的关系

### 1. 装了 `dsh-better-sidebar` 时

该插件接管文件预览后，宿主的代码渲染器根本不在——文件开在它的 CodeMirror 标签页里。本功能**不再让位**，而是同时装饰两种表面：

- 宿主的只读预览（`data-textpreview-*` 锚点），跳转落在预览的行上并高亮 1.2 秒；
- 编辑器的 CodeMirror 视图（以行号槽区分文件与聊天输入框），跳转通过视图的选区与 `scrollTop` 完成，落点是光标所在行，不再有行底色高亮（编辑器只渲染可见行，没有可标记的整行节点）。

一个关键的判断依据：让位的旧逻辑假设邻居会自己提供代码大纲，但它只提供了 Markdown 目录（`MdToc`），并没有代码符号列表——所以让位等于把功能删掉。

### 2. 为什么不用 clangd

`clangd` 能给出语义级符号（宏展开、重载、跨文件），代价是每平台一份约 60–120 MB 的二进制、每工作区一个常驻进程、以及没有 `compile_commands.json` 时的猜测。

而大纲只需要「名字 + 行号」，且需求是瞬时的：打开文件才需要，关掉就该归零。权衡之后这里选择宿主侧一个纯 TypeScript 扫描器——零运行时依赖、Windows 与 Linux 同一份代码、1 万行文件扫描在毫秒级。若将来确实需要语义精度，替换点是扫描器本身（可换 tree-sitter WASM），面板与跳转不必改动。
