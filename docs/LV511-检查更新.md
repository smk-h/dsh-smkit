本文说明 dsh-smkit 的「检查更新」：在设置页点一次按钮，比对 npm 上的最新版本；有新版本时把**安装命令**交给你，可一键复制，插件自己不执行安装。

## 一、 怎么用

### 1. 按钮在哪

打开 设置 → SMKIT，顶部那行 `@smai-kit/dsh-smkit v1.15.0` 徽章右边就是「检查更新」。它跟着徽章放，因为这件事问的是**这个插件自身的版本**，答案也写在同一个位置；它不在功能页签里。

### 2. 三种结果

| 结果 | 界面 | 后续 |
|---|---|---|
| 有新版本 | 弹窗：当前 v1.15.0，最新为 v1.16.0，下面一条可复制的命令 | 复制 → 粘到终端执行 → 重启 dsh |
| 已是最新 | 按钮右边一行灰字「已是最新版本 v1.15.0」 | 无 |
| 检查失败 | 按钮右边一行红字「检查更新失败，请检查网络后重试」 | 可再点一次重试 |

检查期间按钮本身给出反馈：里面的标签换成「检查中」，前面转一条弧线，按钮锁定直到请求返回——不弹骨架屏、不占位，因为等待通常只有几百毫秒。

### 3. 弹窗里的命令

```
dsh plugin --profile web add @smai-kit/dsh-smkit@1.16.0
```

- `--profile` 后面的名字来自宿主真实运行的 profile（`profileContext`），取不到才回落 `web`；
- 版本取刚查到的最新版，所以命令与提示里的版本号永远一致；
- 点「复制命令」写入剪贴板，按钮随即变成「已复制」并锁定，避免重复点；浏览器不给剪贴板权限时（非安全上下文、策略限制），弹窗提示手动复制，命令块带 `user-select: all`，点一下就能全选。

## 二、 为什么只给命令，不自己装

（1）**更新要写进 profile，还要重启宿主。** 插件的宿主半边在 dsh 启动时被 `import` 并执行 `apply`，换掉磁盘上的包并不会换掉运行中的代码；客户端半边的徽章版本还是构建期注入的常量。也就是说，无论谁来装，最终都得由用户重启一次 dsh——既然如此，把这一步留在终端里，用户能看见它发生，比按钮点完假装已经生效要诚实。

（2）**命令用 `add <name>@<version>` 而不是 `update <name>`。** `update` 跟随 profile 里已经声明的 spec：装的是 `github:...#tag` 就还停在那个 tag，装的是 `link:` 就还是本地 checkout，升级不出个所以然。带明确版本的 `add` 才会落到刚查到的那个发布版，也是 dsh 文档里的写法。

（3）**桌面端不给命令。** 桌面应用的 profile 由 Electron 应用独占，`dsh plugin --profile desktop` 会被拒绝，所以那里只显示「请在这个应用的插件页里更新」，复制按钮置灰——给出一个注定执行失败的命令比不给更糟。

## 三、 宿主侧接口

一条只读路由，没有写接口：

```
GET /smkit/api/update/check
→ 200 { current, latest, hasUpdate, installCommand?, error? }
```

- `current`：宿主从自己安装目录下的 `package.json` 读到的版本（模块加载时读，因此升级后重启即生效）；
- `latest`：registry 的 `latest`，取不到时为 `null`；
- `hasUpdate`：`latest` 严格大于 `current`；
- `installCommand`：仅在有更新、且不是桌面端时出现（见第二章第 3 条）；
- `error`：检查本身的失败原因，正常时为 `undefined`。

版本源是 npm 公共 registry 的 `/latest` 端点，只读其中的 `version` 字段：

```
https://registry.npmjs.org/@smai-kit%2Fdsh-smkit/latest
```

之所以查 npm 而不是 GitHub Release：发布的包就在 npm 上，**查到的版本就是能装到的版本**，两者不可能对不上。这也是官方插件管理器安装时读的同一个来源。

请求带 8 秒超时。超时、非 2xx、响应里没有 `version`，都折算成 `error` 并返回 200——按钮需要一个能打印的答案，而不是一个 500。

## 四、 版本比较

只实现做判断所需的那部分 semver：解析 `x.y.z[-pre]`，逐段比数字，然后「预发布版排在它的正式版之前」。

两个预发布版之间按字符串比，因此 `rc.10` 会被判成比 `rc.9` 旧——这是已知偏差，代价说明白就够了：registry 的 `latest` 指向的是正式版，这条路径上不会出现两个预发布版互相比较。

解析不了的版本号一律返回 0（「没有意见」），不会因为 registry 上出现一个奇怪字符串就提示有更新。

## 五、 边界

- **没有自动检查。** 没有定时器、没有启动时探测、结果也不落盘：每次点按钮才发一次请求，页面不开就不联网。
- **不发任何写请求。** 弹窗打开、复制命令、关闭，全程只有那一次 `GET`；测试里对请求序列做了断言。
- **不缓存检查结果。** 新版本随时可能发布，缓存一分钟都可能给错答案，而一次请求的代价只有几 KB。
- **不做安装来源判断。** 用 `link:` / `file:` 装本地 checkout 的，点这个按钮拿到的仍是 npm 版命令，执行后会覆盖本地链接。这是已知取舍：宿主侧要判断安装来源得先知道 profile 的依赖声明，而这套插件目前没有读它的入口。
- **registry 固定。** 没有配置项可以改成私有镜像，内网环境需要改 `DEFAULT_REGISTRY` 常量。
- **升级后仍显示旧版本号**，直到重启 dsh——徽章是构建期常量，不是运行时读取的。这一点在文档与提示里都写明，免得被当成升级失败。

## 六、 实现位置

| 文件 | 职责 |
|---|---|
| [`check.ts`](../src/host/features/update/check.ts) | 读 registry、解析版本、比较版本；失败折算成 `error` |
| [`command.ts`](../src/host/features/update/command.ts) | 按 profile、包名与版本拼出安装命令 |
| [`api.ts`](../src/host/features/update/api.ts) | 唯一一条路由；有更新且非桌面端时附上命令 |
| [`contract.ts`](../src/shared/update/contract.ts) | 两端共用的返回结构 |
| [`UpdateControl.tsx`](../src/client/settings/components/UpdateControl.tsx) | 按钮、旋转图标、结果行、命令弹窗与复制 |
| [`zh.ts`](../src/client/settings/i18n/zh.ts) 与 [`en.ts`](../src/client/settings/i18n/en.ts) | 提示语 |

宿主侧作为一个普通功能挂在 `FEATURES` 里（`updateFeature`），因此只多一条路由、不碰其他功能的挂载顺序；`pluginManager` 之类服务一概不读——这一版不需要任何写入能力，也就不存在「服务没装上就整块功能加载失败」的可能。

客户端没有为它单开特性目录：按钮只出现在设置页顶部那一行，和版本徽章是同一块身份区域，因此组件放在 `settings/components/` 下、样式沿用 shell 层的 `smkit-shell-page-*` 命名空间。旋转图标复用平台层的 `LoaderIcon` 与既有的 `smkit-ui-spin` 动画，没有新增图标文件。

`ConfirmDialog` 为此补了两个可选属性：`confirmLabel`（用自己的动词代替「删除」）、`cancelLabel`（显示结果时用「关闭」而不是「取消」）；主按钮用 `danger: false` 走正常色。

## 七、 实测

- **真实 registry**（2026-11-04）：`checkForUpdate()` 返回 `{ current: "1.15.0", latest: "1.15.0", hasUpdate: false }`——当时 npm 上的 latest 正好是这个版本，构成「已是最新」这条路径。
- **无头 Chromium**（Playwright 1.64.1 自带 Chromium 156，视口 1100×800，真实 `lib/client.js` + React 18 挂载设置节）：断言了按钮与徽章同一行、检查中 `svg.smkit-ui-spin` 的 `animation-name` 为 `smkit-ui-spin` 且按钮 `disabled` / `aria-busy`、弹窗遮罩为覆盖视口的 `fixed`、命令块为等宽字体且 `user-select: all`、`navigator.clipboard.readText()` 取到的正是那条命令、以及全程只发一次 `GET`。
- **Node 测试**：`test/update-check.test.mjs` 覆盖版本比较、registry URL、三种失败降级与路由层「web 给命令 / 桌面端不给 / 无新版不给」；`test/update-button.test.mjs` 在真实客户端 bundle 上覆盖旋转图标、命令原样显示、复制、关闭与失败提示。
