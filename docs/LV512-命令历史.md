本文说明 dsh-smkit 的「命令历史」：在会话输入框里按 `↑` 召回上一条 `/mcp` 命令，按 `↓` 往下翻。

## 一、 它解决什么

dsh 的输入框没有历史记录，按 `↑` 只会滚动对话区；`/mcp` 的命令行又特别长——一条带参数的命令通常是

```
/mcp call mcp__embedded-board__serial_exec {"session_id":"…","command":"…","timeoutMs":15000}
```

这种内容抄一次可以，抄第五次就烦。命令历史让你只按一下 `↑`。

## 二、 怎么用

| 按键 | 当时的状态 | 行为 |
| --- | --- | --- |
| `↑` | 草稿为空 | 召回最近一条 `/mcp` 命令，按键被本功能接管 |
| `↑` | 已在历史中 | 继续往更早翻 |
| `↓` | 已在历史中 | 往更近翻 |
| `↓` | 已是最新一条 | 清空草稿，退出历史 |
| `↑` / `↓` | 草稿非空且未在历史中 | **不接管**，仍是宿主的正常光标行为 |
| `Esc` | 已在历史中 | 退出历史，保留当前草稿 |
| 输入字符、退格、删除 | 已在历史中 | 退出历史 |

召回是「填进草稿」，不是「直接执行」：翻到目标后仍可修改，再按回车提交。

## 三、 记什么

只记**以 `/mcp` 开头的命令行**，例如：

- `/mcp list`
- `/mcp help mcp__embedded-board__serial_exec`
- `/mcp call mcp__embedded-board__greet_tool {"name":"smkit"}`

不记：

- 普通消息（任何不以 `/mcp` 开头的文本）；
- 其他斜杠命令（`/compact`、`/goal` 等）；
- 以 `/mcpfoo` 这类只是前缀相同的词（匹配规则是 `/^\/mcp(?:\s|$)/`，`mcp` 之后必须是空白或行尾）。

记录发生在**按下回车提交的那一刻**，早于命令真正执行。所以一条命令即使执行失败（工具名写错、服务器没连上），它也已经进了历史，按 `↑` 仍可召回修改后重试。

## 四、 限制

| 项 | 限制 |
| --- | --- |
| 条数 | 每个工作区最多 **50 条**，超出后最旧的一条被丢弃 |
| 范围 | 只记 `/mcp` 命令，其余内容一律不记 |
| 存储位置 | 浏览器 `localStorage`，key 为 `smkit.mcp-history:<工作区路径>` |
| 隔离 | 按工作区路径分开存；另一个项目的命令不会出现在这个项目的历史里 |
| 无工作区路径时 | 落在一个共享的 `smkit.mcp-history:*` 下 |
| 去重 | 同一条命令再次提交时移动到最前，不新增副本；因此「50 条」是 50 条**不同**的命令 |
| 新会话 | 空白新会话在第一条消息发出前还没有 agent，输入服务解析不到，`↑` 不响应（不是没记录，是没地方填） |
| 清空浏览器数据 | 历史随之消失，不备份、不跨浏览器、不跨设备、不跨 profile |
| 隐私模式 / 配额满 | 写入失败静默放弃，功能表现为「没有历史」 |
| 模型上下文 | **不进入**。历史只存在浏览器本地，不会变成会话消息，也不占 token |
| 会话日志 | 不写会话日志（不用 `setDraft` 之外的通道），因此导出会话时不包含历史 |

## 五、 存储细节

- 值是一个 JSON 字符串数组，**最新一条在最前**；
- 读取时非数组、含非字符串元素都按「没有历史」处理，不会抛错；
- 写入前先按 key 读出旧数组，去掉与当前命令相同的一条，再插到最前、截断到 50 条，最后整体覆盖写回；
- 键名里的工作区路径来自客户端会话列表（主视图正在显示的那条会话的 `cwd`），拿不到时退化为 `*`。

数据形状示例：

```json
[
  "/mcp call mcp__embedded-board__greet_tool {\"name\":\"smkit\"}",
  "/mcp help mcp__embedded-board__serial_exec",
  "/mcp list"
]
```

## 六、 为什么不做成「所有历史」

终端里 `↑` 召回一切，是因为终端里输入的一切都是命令。聊天输入框里大部分内容是正文，把段落也塞进历史会让 `↑` 变得不可预测——按一下可能召回一整段散文。限制在 `/mcp` 这一条命令上，历史就始终是「几条短命令」，翻起来才有意义。

如果以后要放宽到其他命令（比如 `/compact`、`/goal`），改的是匹配规则那一处，存储与翻页逻辑不用动。

## 七、 与「命令补全」的分工

- 输入 `/` 时宿主弹出的是**命令名**补全（`mcp`、`compact`……）；
- 本功能补的是**整条命令行**（含工具名与 JSON 参数），在提交之后才生效。

两者不重叠：前者帮你记命令名，后者帮你记你自己敲过的那一整行。
