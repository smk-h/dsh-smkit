本文说明 dsh-smkit 的「MCP 调试」页：把 [MCP Inspector](https://github.com/modelcontextprotocol/inspector) 最核心的那一屏搬进 dsh —— 选一台已连接的服务器，选一个工具，填参数，看服务器原样返回的内容和它推过来的通知。

## 一、 它解决什么

设置 → MCP 里能看到「这台服务器有几个工具、参数长什么样」，但看不到**调用一次会返回什么**。想验证一个工具，过去只有两条路：

- 让模型调一次：花一轮 token，结果还要从工具卡片里翻；
- 用 `/mcp call`：不花 token，但参数要手写 JSON，结果是纯文本，图片、通知、耗时都看不到。

这两条路都缺同一件事：**像 Inspector 那样把请求和响应并排摆着看**。调试设备类 MCP 时这一点尤其重要——`serial_exec` 返回的是一整段设备日志，`session_id` 用错时服务器给的是它自己的错误文本，人需要看到原文而不是被投影过的文本。

本页因此不改配置、不接管会话，只做三件事：列服务器、列工具、发一次 `tools/call`。

## 二、 页面在哪

主面板，不是设置弹窗：左侧栏（会话列表那一列）底部图标区多一枚「虫子」图标，点它整个中间区域切换成调试页，就像「记忆系统」那样。再点一次会话就切回去。

为什么不做成 `设置 → MCP` 的一个标签页：三栏（服务器 / 工具 / 结果）在设置弹窗的宽度里挤不下，而 Inspector 的价值有一半来自「同时看见三栏」。

### 开关

设置 → SMKIT → MCP 页里有一项「MCP 调试页」（与「按需 MCP 工具调用」并排，同一个卡片样式），**默认开启**。关掉后左栏入口与主面板**立即消失，不需要重启**；再打开立即回来。

- 两个座位都由 `slots.register` 注册，句柄留着；开关一翻就 dispose 或重新注册（`slots.inject` 那层保持不动——座位是宿主声明的，不随开关走）；
- 真值存 `~/.dsh/mcp-manager.json` 的 `debugPageEnabled`，**缺省视为开启**（这一页先于开关存在，不能因为加了开关就把已有用户的入口收掉）；只有 `POST /settings/debug-page`（body `{ enabled }`）写它；
- 客户端**不为这个开关发请求**：写成功后同时把值镜像进 `localStorage`（键 `smkit.mcp-debug.enabled`），下次加载同步读它决定要不要占座——座位必须在第一帧之前定下来，而给一个多数 profile 都不碰的开关在启动时发一次请求，等于让每个面板都替它付钱；
- 换了浏览器或清了缓存时镜像会缺失：此时按默认（开启）占座，等打开「设置 → MCP」——那里每轮轮询都会把宿主值回报给网关——就会被纠正。代价只是那次访问之前左栏多一个入口。

## 三、 三栏各是什么

### 1. 左栏：服务器

按作用域分组：先是全局（标题「全局」），再是各工作区（标题「工作区 · <目录名>」，悬停可看完整路径）。**空作用域整组不渲染**——包括空的全局组，否则一个没有服务器的标题会紧贴在下一个标题上方，看起来像后者的父级（这正是「全局 / 项目名 / 服务器」被读成三级父子关系的原因）。

每行显示状态色点、服务器名、工具数量、状态文字。状态文字用的是宿主自己的词汇（已连接 / 连接中 / 重连中 / 待认证 / 错误 / 未连接 / 已禁用 / 冲突 / 已配置），与设置页同一套。

选中一台后，下方是它的传输事实：

| 字段 | 内容 |
| --- | --- |
| 类型 | `stdio` / `HTTP` |
| 命令 | stdio 的 `command` + `args` 拼成一行；HTTP 显示 URL |
| 工作目录 | stdio 的 `cwd`（配置了才有） |
| 环境变量 | 只列**变量名**，不显示值 |
| 服务器 | 握手时服务器自报的 `serverInfo.name` · `version` |
| 错误 | 连接错误原文（有错才有） |

未连接的服务器**照样列出来、照样可以点**：点了它之后左栏保持选中，中栏与右栏写明「这台服务器当前未连接」（而不是「这个服务器没有工具」——那是另一回事，且是读者能动手前必须分清的两件事）。它没有工具可跑，因此不会发出任何请求。

两个动作：**重启**、**断开**。两者调的都是设置页那一对路由（`POST /servers/:id/restart`、`/stop`），语义完全一样——重启会重建传输，断开只关连接、保留配置。服务器未连接时页面会说明「工具列表为空是因为它没连上」，而不是让人对着空列表猜。

### 2. 中栏：工具与历史

工具列表来自该服务器的 `tools/list` 快照，显示的是**服务器声明的原始名字与描述**——不是模型看到的 `mcp__<服务器>__<工具>`。调试时你要知道该向服务器要哪个名字。

- 搜索框按名字与描述做子串匹配（不分大小写）；
- 「刷新」立即重读一次 `/servers` 与 `/workspaces`（页面本身每 3 秒也会自动读一次，与设置页同频）；
- 描述最多两行，超出省略：一条工具描述不能占掉五行把其余三十条挤走。

下方「历史」是**本次挂载**内的调用记录（最多 25 条，最新在最上），每条记工具名、成功/失败、耗时、时间。点一条把它当时的返回值原样调回右栏——这是终端 dump 做不到的事。

### 3. 右栏：工具详情

**参数**有两种编辑模式：

| 模式 | 适用 | 控件 |
| --- | --- | --- |
| 表单 | 看得清有哪些参数 | 每个声明参数一行：名字、类型、必填标记、描述，下面按类型给控件 |
| JSON | 从别处粘贴一整个对象 | 一个多行文本框，内容是完整的 `arguments` 对象 |

表单里每种类型对应的控件与转换规则：

| schema | 控件 | 提交时的值 |
| --- | --- | --- |
| `string` | 文本框 | 原样字符串 |
| `number` / `integer` | 数字框 | 数字；非数字、非整数按类型拒绝 |
| `boolean` | `未设置 / true / false` | 布尔 |
| `enum` | 下拉框（含「未设置」） | 命中的那一个成员，保持原类型 |
| `object` / `array` | 多行框 | `JSON.parse` 的结果 |
| 无类型（`any`/`oneOf`） | 文本框 | 能解析成 JSON 就用 JSON，否则当字符串 |

规则只有一条值得记住：**留空等于不发送**。必填项留空时页面直接拒绝（不发请求），可选项留空则整个字段不进 `arguments`——发出 `""` 是另一个请求。

两个模式共用同一份状态：切到 JSON 时把当前表单内容序列化进去，切回表单时按字段名回填。不会因为切模式丢输入。

**运行工具**先把表单收成一个 `arguments` 对象，再 POST 到 `/smkit/api/debug/call`。**参数不合法时什么都不发**：出问题的字段当场标红（红边 + 字段名下红字说明，`aria-invalid` 一并置上），而且一次把所有不合法的字段都标出来，不是只报第一个；填上之后红边立刻消失——标记属于那个值，值一变标记就没了，不需要额外的「清除错误」。

就地标记而不是把原因写进结果区，是因为读的人要改的就是字段本身，不是读一段关于字段的句子。原始 JSON 模式没有字段可标，错误显示在文本框下方。

因此结果区只描述**真正发出去的请求**的回答：

| 结果 | 界面 | 含义 |
| --- | --- | --- |
| 成功 | 绿色「成功」+ 耗时 | JSON-RPC 请求成功，服务器返回 `isError` 不为 `true` |
| 失败 | 红色「失败」+ 耗时 | 服务器把工具报错了（`isError: true`），或者传输层失败（超时、子进程死了、连接被拒）；前者连 `content` 一起显示，后者显示错误原文 |

没发出去的调用**不记进历史**：历史是「调过什么」，不是「点过什么」。

结果的显示分两层：**内容**按服务器给的 content block 渲染（文本用 `<pre>`、图片用 `<img>`、其他类型打印 JSON），**原始 JSON** 折在下面——两者都留，是因为投影后的文本会藏掉人真正要看的字段。

**服务器通知**是这一页独有的东西：服务器主动推的帧（`notifications/message`、`tools/list_changed`、progress……）在宿主里原本只被消费一种（工具列表变化），其余全部丢弃。本功能在传输层把每一帧记进一个按服务器的环形缓冲，页面读出来显示。展开任一帧可看它的 `params`；参数超过 8 KB 的帧只留方法名并标注「参数过大，已省略」，不塞一个看起来完整的截断体。

## 四、 数据从哪来

| 用途 | 路由 | 说明 |
| --- | --- | --- |
| 服务器 + 工具 + 状态 + 服务器自述 | `GET /smkit/api/servers`、`GET /smkit/api/workspaces` | 与设置页同一对接口，**不新增** |
| 调一次工具 | `POST /smkit/api/debug/call` | 新增；body `{ id, tool, arguments }` |
| 读通知 | `GET /smkit/api/debug/notifications?id=<服务器 id>` | 新增 |
| 清通知 | `POST /smkit/api/debug/notifications/clear` | 新增；body `{ id }` |
| 读/写页面开关 | `GET /smkit/api/settings`、`POST /smkit/api/settings/debug-page` | 新增写路由；body `{ enabled }` |

`id` 是服务器的**全局唯一 id**（工作区服务器是 `ws-` 开头的确定性 id），因此一个 id 就能定位到全局或任一工作区的服务器，不需要再带作用域。

调用落在**同一个活连接**上：`tools/call` 直接发给模型调用的那条传输。这是关键——设备类 MCP 的串口 / SSH 会话在服务器进程里，另起一个 inspector 进程连同一个命令，连到的是另一个实例，调试的不是同一个东西。

超时沿用「设置 → MCP → 高级」里的工具调用超时（默认 60 秒），每次请求现读，改完不需要重连。

## 五、 生命周期：什么时候卸载、多久轮询一次

### 1. 它是一块主面板，切走就卸载

页面注册在两个座位上（与「记忆系统」插件同一对）：

| 座位 | 作用 |
| --- | --- |
| `main`（keyed，key `smkit-mcp-debug`） | 页面本体，占满中间区域 |
| `sidebar.panellist`（list，id 与 key 相同） | 左栏那枚虫子图标，点它切到这一页 |

宿主只渲染**当前选中的**主面板。进入某个会话、或点开另一个面板，这棵组件树就被卸载：DOM 消失、`useEffect` 的 cleanup 清掉轮询定时器、所有 `useState` 归零。

实测（无头浏览器，同一轮操作）：

```text
面板里做完一次调用：mounted true · 选中 embedded-board · 工具 greet_tool · 历史 1 条 · 结果 Hello, smkit!
切到会话：          mounted false · 服务器列表 [] · 历史 0 条 · 结果 null
宿主侧：            sm_demo:connected:1 · embedded-board:connected:39   ← 连接还在
再切回来：          mounted true · 选中 sm_demo（自动选第一台已连接）· 工具 null · 历史 0
```

### 2. 卸载时什么消失、什么留下

| 东西 | 切走后 | 属于谁 |
| --- | --- | --- |
| 页面 DOM、三栏、全部 `useState`（选中的服务器/工具、参数草稿、结果、历史、复制状态） | **消失** | 页面组件 |
| 两个轮询定时器（状态 10 秒、通知 3 秒） | 停（effect 的 cleanup） | 页面组件 |
| MCP 连接、工具列表、服务器进程 | **保留** | 插件宿主（`runtime`） |
| 服务器通知环（每服务器 ≤50 条） | **保留并继续记录** | 插件宿主（`runtime.debugNotifications`） |

通知环刻意留在宿主侧：离开期间推来的帧除了这一页没有别处能看，所以切回来仍能看到（参数超过 8 KB 的帧只留方法名并标注截断）。因此「切回来是全新一次」只针对页面自己的状态，不包括服务器的实时状态与通知。

浏览器端内存：整页的 JS 状态是几十个工具行 + 最多 25 条历史 + 最多 50 条通知，量级几百 KB，随卸载交给 GC；宿主侧 RSS 在面板开着轮询 30 秒前后只差约 3 MB（484 → 487 MB，噪声级）。

### 3. 轮询：两条时钟，只在你看着这一页时走

挂载时立即读一次全部三个接口，之后**按两个节奏**重读：

| 请求 | 大小 | 节奏 | 为什么是这个节奏 |
| --- | --- | --- | --- |
| `GET /servers` + `GET /workspaces` | **37 KB**（39 个工具，含每个工具的完整 schema）/ 0.5–1.0 ms 各自 | **10 秒** | 它回答的是「谁连着、有哪些工具」。这页切走即卸载、挂载即重读，所以定时器只需覆盖「你正看着时别处发生的变化」：工作区被打开、外部改配置、服务器掉线。三项都罕见，掉线还会在下一次调用时立刻暴露 |
| `GET /debug/notifications?id=…` | 20 B（空环）/ 0.4 ms | **3 秒** | 这是唯一「无人请求也会来」的东西：服务器推的 log / progress 帧。而且它便宜——两个负载差三个数量级，所以分两条时钟 |

合计约 **3.7 KB/s**（37 KB / 10s）；CPU 约 **0.006% 单核**。页面的动作——点刷新、跑一次工具、重启/断开——**都会立刻重读**，不等定时器。

**面板被切走时是 0**：实测切走后 10 秒内调试页请求 0 次，日志里只剩通知功能自己的心跳。注意「切走」指面板卸载；只是把浏览器标签切到后台、面板仍开着时，两条时钟照常走（`document.hidden` 暂停还没做，见下）。

### 4. 为什么是轮询而不是长连接

「记忆系统」（`dsh-mnemon`）不轮询：它的客户端一个 `setInterval` 都没有，挂载时 `store.load()` 读一次，之后靠 `remote` 常驻通道推送 + `useSyncExternalStore`。实测它打开着的 15 秒里 0 次数据请求（只有别处的心跳），切走时同样卸载（`mnemonShell: false`）。

本插件的客户端半区只注入 `slots / locale / sessions / theme`，与宿主之间的契约就是 `/smkit/api/*` 的普通 fetch。走长连接要引入 `remote` 与 `remote.<namespace>` 两个服务、再在宿主侧写一条事件流——为一个调试页加一整套传输，换来的只是省下 12 KB/s 与 0.02% CPU。

已经做掉的：状态 3 秒 → **10 秒**、两条时钟分开（通知保持 3 秒）。

还没做、也想清楚的：

- `/workspaces` 的 37 KB 随「所有工作区的所有工具」线性增长，工具特别多时要治（可选：给左栏一个轻量接口，工具列表等选中服务器时再取）；
- `listWorkspaces()` 对「没打开过的工作区」每轮做一次同步 `readFileSync`，网络盘上会慢（设置页原本就是这样）；
- 剩下两档更省的做法：`document.hidden` 时两条都暂停；或彻底去掉状态定时器，只留挂载 + 手动刷新 + 动作后刷新（代价是服务器自己掉线不会自己变色）。

## 六、 不做什么

| 不做 | 原因 |
| --- | --- |
| 增删改服务器配置 | 那是设置页的事；一页两用会让人不敢点 |
| Resources / Prompts 面板 | 本插件只维持 `tools/*` 与 `initialize` 的传输面；`resources/list`、`prompts/list` 需要通用 `request()`，而 HTTP 传输不暴露它 |
| 临时连接一个不入库的服务器 | 同上：临时连接等于再写一套传输生命周期与凭证处理，与「调试已配置的服务器」是两件事 |
| 回放历史到磁盘 | 历史只活在这次挂载里；跨刷新恢复一个「选中的服务器」会让人误判当前连的是谁 |
| 采样 / elicitation / roots | 宿主不发起这些请求，页面没有可展示的东西 |

## 七、 已知限制

| 项 | 限制 |
| --- | --- |
| 主面板 id | `smkit-mcp-debug`；与左栏图标的条目 id 必须一致，否则页面在但点不开 |
| 工作区服务器 | 只在「有 agent 打开过该工作区」时才真正连接；未打开的工作区里显示的服务器状态是「已配置」，工具列表为空，点它会提示未连接。这类行的 id 由「工作区路径 + 服务器名」哈希得出（`ws-` 前缀），每次读配置都相同——否则页面按 id 寻址的选择会在下一次轮询时丢失，表现为「点一下又跳回第一台」 |
| 通知条数 | 每台服务器保留最近 50 条，超出丢最旧 |
| 高度分配 | 工具描述 ≤96px、参数表单 ≤min(30vh, 260px)、结果 ≤min(34vh, 300px)、通知 ≤160px，各自内部滚动；右栏本身不再因为某一块变长而整体滚动（暗色 1440×900 与 1280×720 实测：右栏 scrollHeight == clientHeight） |
| 历史条数 | 本次挂载最多 25 条 |
| 图片结果 | 以 `data:` URL 直接渲染；特大图片会让 DOM 变大，页面不做缩放或下载 |
| 服务器名 | 显示服务器自己声明的名字：全局用配置名，工作区用配置名；两者可能同名不同源（工作区重名规则允许），以分组区分 |
